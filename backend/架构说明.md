# Flash Training v2 架构与修改入口

主流程：选择岗位任务→生成自足材料→文字作答→按行动量规取证→场景内学习建议。课程知识是概念来源，行动原子描述可观察的动作，岗位任务组合2–4个原子。初始内容是教学示例，没有行业验证或职业资格认证含义。

## 数据流与边界

HTTP 路由接收参数并调用应用服务；应用服务组织用例；领域层定义模型、约束和协议；基础设施实现 SQLite 与模型访问。main.py 和 bootstrap.py 组装依赖，底层不反向依赖路由。

data/career_catalog.json 定义岗位、知识、原子、先修边与任务。默认新库 data/flash_training_v2.sqlite3 初始化时播种，启动不导入旧技能库和历史，不自动删除用户配置的数据库。schema v2及两种历史v3在备份后增量升级至v4，同时保存迁移诊断和学习项目；目录格式仍为2。启动时只为内容未修改的内置v1原子补充四类条件并升级定义版本，其他目录改动不隐式覆盖运行库。

练习先保存题目与定义快照，提交时使用保存材料，不重新出题。读取会话后关闭读事务，再调用模型；校验后在写事务内重新检查状态并保存结果。事务实现负责提交、回滚与关闭连接，仓库不各自提交。

## 四种职责

| 职责 | 输入与结果 |
| --- | --- |
| 任务设计者 | ContentService.generate 接收任务和有效参数，模型生成完整题面材料与参考答案 |
| 原子映射者 | 确定性读取目录与目标，检查原子引用、关联及先修约束，不让模型随意创造能力节点 |
| 证据评估者 | 模型按保存材料、答案和量规评估，应用层校验目标集合及答案原文引用 |
| 学习规划者 | 确定性结合目标原子、先修条件和当前场景证据给出下一步与理由 |

四者复用已有服务、模型适配器和事务，没有自主执行代码、联网取数、外部工具或新增 Agent 框架。自定义任务提案只能组合已有原子，模型 JSON 不能直接成为任意目录写入命令。

## 迁移训练闭环

`/bridge` → `practice/start`（bridge_case_id 和可选 source_session_id）→ 固定教学材料 → 原有 `practice/submit` → `bridge/sessions/{id}` 展示配对条件与诊断题 → `bridge/sessions/{id}/diagnosis` 保存诊断选择与结果。

- `domain/bridge.py` 定义带版本的固定案例和规则探针。基线与变式明确改变和保留的条件，诊断标准答案只存在服务端。
- `application/practice.py` 校验受控任务参数与关联会话，复用会话快照、提交幂等和证据事务。
- `application/content.py` 为受控案例返回固定材料，普通任务仍使用模型生成；文字交付评估继续按快照中的原子定义调用模型，并检查分值及原文引用。
- `application/bridge.py` 组织成对观察与诊断，检查用户、完成状态、量规及辅助使用，再决定是否给出分差。诊断选择单独持久化，不当作额外能力得分。
- `frontend/src/pages/Bridge.tsx` 和 `frontend/src/components/BridgeFeedback.tsx` 承接学习路径与诊断；图谱继续展示原子、课程、任务关系，增加四类使用条件。

受控案例选择和诊断分析属于规则 Agent 职责，评估属于模型职责；执行记录明确区分。多 Agent 开发协作按内容、后端、前端分工，主 Agent 负责共享模型、目录升级、集成复核与交付。运行时没有增加自主工具调用框架。

综合题要求显式提交中间依据，当前只评价已有三个原子；不声称已经建立独立的过程因果归因模型。诊断只检查公式、分母和可比性三个解释，单次探针结论是支持或反驳某个假设的线索，不是确定的认知诊断。受控变式尚未验证等难，重复材料可能带来记忆效应，不能用一组成对分差证明迁移训练有效。

定义可跨场景复用，表现不跨场景自动共享。课程学习、总分或自评不等于观察证据。引用校验能阻止答案中不存在的引文，但不能证明模型语义评分正确；指标题要求提供算式便于复核。

## 下次修改入口

- 增加任务或课程关联：调整目录稳定 ID、知识与原子组合；已有库须显式更新。
- 修改原子：调整动作、输入输出、边界、量规及四类使用条件；旧会话仍读定义快照。修改量规需提升定义版本，避免把不同依据的评分当作可比较数据。
- 修改受控练习：调整 bridge 中的固定案例及版本；材料或受控差异改变时提升 `COMPARISON_VERSION`，阻止与旧材料配对。确保单一变式的材料信息一致；增加诊断时同步题目、规则解释和前端响应类型。
- 替换模型接口：infrastructure/ai.py；模型、地址和密钥在 .env.ai。
- 修改提示词与证据格式：application/content.py，同步调整领域结果模型及调用方。
- 修改推荐：调整确定性规划规则，保留场景、先修与证据来源边界，不放进路由。
