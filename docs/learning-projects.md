# 学习项目：前三步实现说明

本版把学习目标、短诊断、针对性帮助和新任务独立复测连成可持续保存的流程。首页的“创建或继续学习目标”进入 `/projects`。原来的单次任务练习和历史记录继续可用。

## 如何体验

1. 新建目标，如“把数据库知识用于订单数据分析”，填写已有基础、期望交付物；可粘贴文字资料。
2. 练习范围选择“数据库 → 订单数据分析”，开始尝试。也可以只保存目标为待规划，稍后手动选择范围。
3. 分别填写净收入数值和简短理由。系统逐项检查行粒度、连接倍增、净收入核验。
4. 证据充分立即结束；明确错误直接提供帮助；关键证据缺少时最多追问两次，每次只问一个点。创建时可改为一次或零次，追问可跳过。
5. 获取提示、解释或局部练习，局部练习回答可以保存。再用未在本项目中展示过的新材料独立复测。错误或证据不足会回到补弱；只有新任务独立提供全部目标的证据时标记“本次复测通过”。
6. 图谱和能力证据页可以检查原始引用、原因、下一步和项目过程。刷新页面后，继续当前轮和草稿。

内置案例1的核算基准为订单400元减退款60元，净收入340元。有效解法包括分别求和、先汇总退款再左连接、适当子查询；不要求唯一SQL。只报340元不能证明理解一对多连接。后续案例在开始复测时才显示；每项目五份材料，用完后明确停止，不循环冒充新题。

## 诊断的效率与边界

- 每次回答只调用一次模型，同时获取逐项证据和候选追问；是否真的追问由明确规则决定。
- 默认最多两次追问。只追问关键、不确定且有信息价值的问题，同一轮不会重复追问同一原子。存在明确错误时直接帮助。
- `supported` 表示当前回答有支持证据；`gap` 必须对应明确错误；`uncertain` 区分缺少证据和任务本身观察不了。数值正确不会自动支持所有原子，数值错误会由确定性规则标记核验缺口。
- 核对原子ID、状态一致性及逐字引用。模型返回无效依据时拒绝写入判断，保留已有进度，不伪造评分。
- 独立初次回答、新题复测、追问和声明使用帮助的表现分别记录。追问后补齐的证据不会直接变成独立复测通过。
- 不输出掌握概率，不把新诊断强行转换为0到10分。跨情境迁移仍需额外独立取证，不由本次通过自动推断。
- 学习项目接口需要登录，服务端从会话取得 `user_id`，请求体不接受用户身份字段；不同账号的项目、草稿和原子观察分别保存。目录定义仍由所有账号共享。

内置数据及帮助由开发者编写、计算可核验，**尚未经教师或真实用户验证**。模型的语义判断、追问价值仍需用人工标注案例评测；自动化测试使用可控模型替身，不能证明真实模型诊断准确率。

## 数据与结构

- `domain/projects.py`：项目快照、轮次、发现、帮助和事件；`domain/project_commands.py`：输入契约。
- `application/projects.py`：流程规则、独立复测边界、草稿和操作协调；`application/project_coach.py`：诊断及帮助提示词、模型结果验证。
- `domain/learning_cases.py`：首个可核验场景、显式原子量表、不同数据和帮助。通用目录任务使用原有内容生成器，结合项目背景生成材料并拒绝与本项目旧材料完全相同的题目。
- `infrastructure/repositories/projects.py`：持久化、操作去重、并发占用、版本检查和原子观察。模型调用始终在数据库事务之外。
- `api/projects.py`：薄接口，统一位于 `/api/v3/projects`，提供新建、列表、详情、操作和草稿。
- `domain/evidence_views.py` 与 `application/evidence.py`：把新观察与已有单次练习证据汇总，不覆盖旧历史。
- 前端 `Projects.tsx`、`ProjectWorkspace.tsx`：目标入口和工作台；服务端自动保存草稿，浏览器保存即时刷新的恢复副本。并发版本冲突会拒绝覆盖。

数据库由schema v2、两种历史v3或v4增量升级为v5，**目录版本仍为v2，文件名保持原样**。保留或补齐 `learning_projects`、`project_operations`、`project_observations` 与 `bridge_diagnoses`，新增账号和登录会话表，保留学习记录和项目快照；目录启动逻辑会为未自定义的原始原子补充已编写的条件字段；首次升级前自动在数据库旁 `backups/` 生成一致性备份。可以用 `python -m app.manage inspect` 检查版本与完整性。

AI配置沿用 `backend/.env.ai`，前端没有密钥。修改诊断提示词在 `application/project_coach.py`，底层API适配仍在 `infrastructure/ai.py`。

## 验证

在backend目录执行 `python -m unittest discover -s tests -v`；在frontend执行 `npm test`、`npm run lint`、`npm run build`。

新增测试覆盖：迁移备份与失败回滚、目标待规划、接口契约、用户范围、逐字引用与目标校验、正确结果但证据不足、替代方法、提前停止、两次追问上限和跳过、数值规则覆盖错误模型判断、帮助与局部练习不增加掌握证据、独立复测成功和失败、复测后追问不冒充独立完成、草稿恢复与旧版本拒绝、重复请求、并发提交及事务外模型调用、材料耗尽。

浏览器验收使用临时数据库和模型替身，实际经过页面、HTTP接口与数据库，覆盖创建→草稿刷新→追问→跳过→帮助→局部练习→新题通过→新题失败→图谱/证据回看，并检查桌面和手机宽度。不会写入用户的正式学习数据。

## 后续范围

本次完成计划前三步。任意学科的自动原子拆解、原子审核/版本治理、论文与录音文件解析、资料精确溯源和真实用户学习效果实验属于后续步骤。粘贴资料当前作为项目背景保存；内置案例使用固定材料，通用任务可把背景用于生成模拟题，不代表已实现文档学习或事实溯源。
