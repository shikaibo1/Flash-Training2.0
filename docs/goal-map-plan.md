# 目标驱动图谱与能力证据时间线

状态：代码已接入，通过现有自动检查及临时环境专项验证。范围仅包含这两项，不包含工作模拟、资料解析或作品导出；真实模型质量及学习效果仍待验证。

## 用户流程

从学习目标卡片进入“查看目标图谱”，或在 `/graph` 选择已有项目。默认仍可浏览完整目录图。

目标图突出本项目的任务、目标原子、递归前置能力、支撑知识和所属职业。点击原子可查看适用条件、同情境证据时间线和下一步练习。完成练习返回图谱时重新读取证据，不依赖上次页面的缓存。

示例：目标是“用数据库完成订单净收入分析”，图谱展示行粒度、连接倍增及结果核验。连接倍增若只有追问后的支持证据，显示“辅助或追问后有证据”，推荐新材料下的独立尝试，不显示“已掌握”。

## 页面与交互

| 区域 | 内容与操作 |
| --- | --- |
| 目标选择 | 全图 / 我的项目；URL 保存项目和选中节点，支持刷新与返回 |
| 目标摘要 | 目标、任务情境、当前阶段、独立证据覆盖数；称为证据覆盖，不称为掌握率 |
| 关系画布 | 目标原子和前置原子使用不同外圈；状态由文字、符号及颜色共同表达 |
| 下一步建议 | 给出推荐原因、目标原子和练习入口；允许直接尝试，不强制解锁 |
| 原子详情 | 保留动作、输入输出、条件、边界、评分依据和直接关系 |
| 证据时间线 | 按情境查看证据、加载更多、回到原始作答；支持明确选择两条记录并排查看 |

沿用已有拖动、平移、缩放、定位和重排。按账号及项目保存个人布局和显示偏好；仅保存视图，不改变知识关系。读取时校验数值与节点是否仍存在，写入失败明确提示。窄屏采用画布在上、详情在下的顺序，保留可用的节点列表和键盘操作。

未绑定任务的项目提示“先选择练习范围”，提供返回项目入口；目标加载失败显示重试，不静默切换全图。筛选导致没有节点时区分“没有匹配”与“没有绑定”。

## 证据的含义

五种状态沿用现有语义：尚未测量、发现缺口、辅助或追问后有证据、独立完成证据、尚不确定。没有分数不填零，没有回答不直接判错。

每条记录显示时间、情境、来源、作答阶段、辅助声明、原文引用、判断理由和下一步建议。普通练习评分与项目定性判断分开展示，不强制换算。没有引用的记录如数值规则检查，应明确显示依据类型，不补写用户原话。

目标视图默认查看该情境下的本人证据，不把其他岗位的成功自动传播过来；可另选只看本项目。初答与独立复测分别标注，追问后成功不计作独立复测通过。

比较两条记录只展示可核查差异：当时任务、辅助情况、引用和判断。条件或定义版本不同则说明不可直接比较，不自动计算学习增益或声称因果效果。

## 后端与数据边界

复用 `GraphService`、`EvidenceService`、项目快照及现有仓库。API 只读取，不新增模型调用、不改变成绩、不新增数据库表。认证继续从 Cookie 会话取得用户身份。

目标图使用已保存的任务和原子快照；前置能力及知识可引用当前目录，但要标明其来源边界。缺失引用、前置循环和版本差异必须有明确提示。递归遍历须去重并检测循环，不能把节点间最短路径当作最佳学习路线。

推荐从现有规则中抽出本次可复用部分，由全局推荐和目标推荐共同调用；保持全局入口行为。目标入口限制任务情境与相关原子，候选任务不得包含无法找到定义的原子。没有合适任务时明确说明并提供返回项目入口，不捏造补练。

时间线读取本人全部相关证据，合并普通练习与项目观察后排序分页，不能从仪表盘最近 100 条截取。原子已从目录移除但历史仍存在时保留可查能力。指定项目时必须先验证所有权。

## 接口约定

- `GET /api/v2/graph/projects/{project_id}`：返回目标信息、相关图、目标及前置原子 ID、情境状态、推荐与警告。
- `GET /api/v2/evidence/atoms/{atom_id}/timeline`：可传 `context`、`project_id`、`offset`、`limit`，默认每页 20 条，上限 100；返回记录、总数和分页信息。
- 每条时间线记录包含稳定 ID、来源、情境、阶段、辅助状态、证据状态、引用、理由、下一步、时间、可空分数，以及原项目/轮次或会话/任务标识。

前端共享类型集中声明，所有请求通过现有 `api.ts`。切换项目、原子、情境或账号时，迟到的旧请求不得覆盖新视图；分页切换不混入上一个筛选的记录。

## 实施职责与执行方式

原定使用 GPT-6.1 Sol（high）分工如下；因本次子 agent 的任务正文显示异常，按用户后续要求改由主会话直接完成代码与整合，没有把本次实现记为并行协作成果。

1. 后端 agent：读取模型、相关图构建、复用推荐、证据分页、认证路由。
2. 图谱 agent：项目入口、选择器、目标关系图、状态图例、练习入口、个人视图保存。
3. 时间线 agent：证据卡片、筛选、分页、原始来源入口和两条证据的并排查看。

实际实现仍沿用上述职责边界：`GraphService.project_plan` 组织目标关系与推荐，`EvidenceTimelineService.timeline` 合并并分页；前端 `KnowledgeGraph` 组织范围与详情，`KnowledgeGraphCanvas` 管理交互与偏好，`EvidenceTimeline` 管理历史筛选和并排查看。共享类型及请求分别集中在 `types/goalGraph.ts` 与 `lib/api.ts`。

证据状态沿用全局规则，按原子 ID 与情境汇总，未逐条匹配历史定义版本；目标图会提示此限制，时间线显示当时快照版本。比较仅供核对原始依据，即使版本号相同也不证明材料或难度等价。分页按请求当时的历史排序；其他窗口新增记录后，可用“刷新证据与图谱”从头重新读取。

## 交付标准

- 选中项目后只突出与该目标有关的关系，保留原有图谱交互和定义详情。
- 每条建议解释推荐原因并能进入可用练习或原项目。
- 同一原子的追问、辅助和独立复测可清楚辨认，来源可回看。
- 超过 100 条历史仍可翻页查看；空结果、加载失败和不确定判断各自明确。
- 切换账号不显示其他账号的项目、证据或个人布局。
- 不改写历史成绩，不强行给定性证据打分，不将一次成功等同于长期掌握。
